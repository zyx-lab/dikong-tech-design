# 业务接口扩展指南（给研发）

本文说明如何在现有双平面架构下扩展业务接口（`/api/v1/*`）。

## 1. 先确定边界
1. IAM 管理能力（用户、角色、scope、审计）只能放在 `/internal/auth/*`。
2. 业务资源能力（无人机、任务、飞行记录等）只能放在 `/api/v1/*`。
3. 业务接口禁止直接操作 `Group/Permission/StaffType`。

## 2. 扩展步骤总览
1. 设计业务资源模型。
2. 为资源定义白名单权限码。
3. 接入 DRF 视图与鉴权。
4. 配置 Group 与 scope。
5. 补测试与文档。

## 3. 定义业务权限码（白名单）
在业务模型 `Meta` 中显式定义权限，不使用默认 CRUD。

```python
class Drone(models.Model):
    code = models.CharField(max_length=64, unique=True)
    name = models.CharField(max_length=64)
    created_by_staff_id = models.BigIntegerField(null=True)

    class Meta:
        default_permissions = ()
        permissions = [
            ("view_drone", "可查看无人机"),
            ("change_drone", "可编辑无人机"),
            ("delete_drone", "可删除无人机"),
            ("drones_control", "可控制无人机"),
        ]
```

执行：
```bash
python manage.py makemigrations
python manage.py migrate
```

## 4. 接入业务接口（/api/v1）
1. 路由放到业务平面（如 `apps/xxx/urls.py`，挂载到 `/api/v1/*`）。
2. 视图使用统一权限校验：
- 动作接口：`ScopedActionPermission`
- 列表范围过滤：`ScopedQuerysetMixin`
3. 不写 Group 名称判断，只写权限码。

示例：
```python
class DroneViewSet(ScopedQuerysetMixin, ModelViewSet):
    permission_classes = [ScopedActionPermission]
    permission_map = {
        "list": "drone.view_drone",
        "retrieve": "drone.view_drone",
        "update": "drone.change_drone",
        "partial_update": "drone.change_drone",
        "destroy": "drone.delete_drone",
    }
```

## 5. scope 数据前提
1. 要支持 `OWN`：资源需有创建人字段（如 `created_by_staff_id`）。
2. 要支持 `ASSIGNED`：资源需有指派字段或关联表（如 `assigned_staff_id` / `mission_assignees`）。
3. 列表接口必须在 queryset 层过滤，不靠对象逐条过滤。

## 6. IAM 配置流程（上线前）
1. 在内部管理平面配置 `Group -> Permission`。
2. 配置 `Group + Permission -> Scope`。
3. 配置 `StaffType -> Group`。
4. 用 `/internal/auth/me/permissions` 验证生效。

## 7. 测试要求
1. 未登录请求：应拒绝。
2. 无权限请求：应返回 `PERMISSION_DENIED`。
3. 有权限但无 scope：应返回 `SCOPE_NOT_CONFIGURED`。
4. `OWN/ASSIGNED/ALL` 三种范围都要覆盖测试。
5. 关键写操作需有审计日志断言。

## 8. 文档要求
1. 业务接口写入 `/api/v1/docs/` 可见文档。
2. 每个接口标注所需权限码。
3. 每个列表接口标注 scope 行为。

## 9. 常见错误
1. 在业务代码里硬编码 Group 名称。
2. 让业务接口直接改 IAM 表。
3. 忘记配 scope，导致“有权限但全拒绝”。
4. 把 IAM 接口暴露到公网。
