Track A

航线上传链路：从方案到切换完成

目标是把 route 流程从旧上传方式切到更清晰的 KMZ 直传链路。

本周完成

  • 补齐直发设计、KMZ 直传设计和验证计划。
  • 新增 route download URL 字段，补持久化和测试覆盖。
  • 完成 direct upload cutover，更新 route 读写与联调契约。
  • 补上上传清理逻辑，减少旧 wayline 残留。
  • 新增迁移，正式移除不再需要的 XML 字段。

产生的结果

  • 航线主链路更接近真实业务使用方式，减少中间态。
  • 对接方可以直接按 KMZ 进行上传、查询和下载。
  • 旧流程清理后，后续 route 模块维护成本更低。

相关提交关键词：`direct publish`、`kmz direct upload`、`download url`、`xml field removal`

Track B

任务 / 媒体模型：从耦合状态收口到可控状态

目标是把任务和媒体的业务边界拉清楚，让后续同步、绑定和删除行为更可控。

结构性调整

  • 为 Mission 和 MediaFile 增加 trace 字段。
  • 实现 soft delete，并补相关防护逻辑。
  • 去除 Mission 对 DJI job 的直接耦合，改为本地任务记录。
  • 将媒体同步收敛成按设备入库，不再混入不必要的任务同步职责。

新增能力

  • 支持媒体文件显式批量绑定 Mission。
  • Mission 绑定关系可以反向约束 route 修改。
  • API schema 补齐字段类型提示，避免联调理解偏差。

Mission 本地化

数据更可追

软删除 + Trace

操作更明确

媒体批量绑定
