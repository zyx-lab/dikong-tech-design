PRODUCTION ONBOARDING

接手低空平台，按生产顺序完成部署。

正式环境统一使用 PostgreSQL。先确认域名、端口和持久化目录，再配置密钥，依次启动基础设施与应用，最后完成账号和业务链路验收。

安装与拉取代码

以下条件没有确认前，不要启动应用容器。

运行环境

主机与入口

Docker Compose v2 可用；域名已解析；8000、9000、9001 按网络策略开放，公网入口由 HTTPS 反向代理承接。

持久化

数据与备份

PostgreSQL 和 MinIO 数据卷位于持久磁盘；上线前明确备份、恢复和保留周期。

01

确认 Docker 与端口

docker --version docker compose version ss -lntp | grep -E ':8000|:9000|:9001' || true

8000 为 API，9000 为对象存储 API，9001 为 MinIO Console。正式环境由防火墙和反向代理限制访问。

02

拉取指定发布版本

git clone git@github.com:zyx-lab/dikong-tech-design.git cd dikong-tech-design git fetch --all --tags git checkout <release-tag-or-commit>

生产环境使用明确的 tag 或 commit，不直接跟随浮动分支。

03

启动配置向导

docker compose up -d --build onboarding ssh -L 8080:127.0.0.1:8080 <deploy-user>@<server>

通过 SSH 隧道访问 http://127.0.0.1:8080/onboarding/。配置写入完成后执行 docker compose stop onboarding。

01

Django 与 PostgreSQL

数据库容器和应用读取同一组账号配置。

DB_ENGINE=postgres DB_NAME=dikong DB_USER=dikong_app DB_PASSWORD=<strong-database-password> DJANGO_SECRET_KEY=<long-random-secret> DJANGO_DEBUG=false DJANGO_ALLOWED_HOSTS=api.example.com
02

MinIO 与可选媒体 Webhook

对象存储 endpoint 必须是用户浏览器可访问的 HTTPS 地址；媒体 Webhook Token 可留空。

MINIO_ROOT_USER=<storage-access-key> MINIO_ROOT_PASSWORD=<strong-storage-secret> OBJECT_STORAGE_BUCKET_NAME=dikong-route-covers OBJECT_STORAGE_ENDPOINT_URL=https://files.example.com DJI_INTERNAL_API_TOKEN=
03

检查最终配置

确认 Compose 展开结果中没有示例密码、开发密钥或错误域名。

docker compose config

HTTPS 反向代理

示例使用 Caddy。它会自动申请证书，并原生代理 WebSocket。

01

配置 API 与对象存储域名

# /etc/caddy/Caddyfile api.example.com { reverse_proxy 127.0.0.1:8000 } files.example.com { reverse_proxy 127.0.0.1:9000 }
02

校验并重载

sudo caddy validate --config /etc/caddy/Caddyfile sudo systemctl reload caddy sudo systemctl status caddy --no-pager
MinIO Console 的 9001 端口只允许内网或 VPN 访问。不要将 PostgreSQL 5432 和 Redis 6379 暴露到公网。

按顺序启动

正式环境六个服务都要部署；先让基础设施健康，再启动应用。

1. db · PostgreSQL 16

业务数据、账号、权限和任务状态的唯一持久化数据库。

等待 healthy

2. redis

Channels、WebSocket 广播和 DJI worker 协作。

等待 healthy

3. minio + minio-init

对象存储常驻；初始化任务创建 bucket 后正常退出。

等待 healthy / completed

4. web + v2-dji-worker

ASGI API 与 DJI MQTT 后台处理必须同时常驻。

保持 Up
01

启动基础设施

docker compose up -d db redis minio minio-init docker compose ps
02

构建并启动应用

web 启动时自动执行迁移、权限目录同步和对象存储迁移。

docker compose up -d --build web v2-dji-worker docker compose ps

创建账户

平台业务管理员和 Django Admin 是两套入口，按实际职责创建。

01

创建平台管理员

仅限全新数据库首次部署。该命令会重建 v2 初始化数据，已有业务数据时禁止使用 --reset。

read -s ADMIN_PASSWORD docker compose exec web python manage.py bootstrap_v2_system --reset \ --username <platform-admin> --password "$ADMIN_PASSWORD" --noinput unset ADMIN_PASSWORD
02

创建 Django Admin 超级用户

只给需要维护 Django 数据的运维人员使用。

docker compose exec web python manage.py createsuperuser
03

已有数据库只同步目录

更新版本后可以安全同步权限、角色和菜单，不重建业务数据。

docker compose exec -T web python manage.py bootstrap_v2_system

创建 DJI 连接

DJI 上云地址、账号和密码由平台用户配置，保存在 PostgreSQL 的连接记录中，不写入部署环境变量。

01

登录并取得 Bearer Token

在 Swagger 中使用平台管理员登录，然后通过授权按钮设置返回的 Token。

打开 Swagger查看 OpenAPI Schema
02

通过 API 创建上云连接

POST /api/v2/resource/dji-connections Authorization: Bearer <token> Content-Type: application/json { "name": "正式 DJI 上云", "baseUrl": "https://dji-upstream.example.com", "username": "<upstream-user>", "password": "<upstream-password>", "loginFlag": 1 }
03

可选：媒体上传 Webhook

只有上云侧要主动推送媒体上传结果时才配置；没有配置 Token 时跳过本步。

POST https://api.example.com/api/internal/dji/callbacks/media-upload X-DJI-Internal-Token: <DJI_INTERNAL_API_TOKEN>
04

验证发现与 Worker

创建连接后调用该连接的 discover 接口，并确认 worker 日志持续运行且没有认证、MQTT 或 Redis 错误。

docker compose exec -T web python manage.py run_v2_dji_worker --once docker compose logs --tail=200 v2-dji-worker

备份与恢复

上线前必须实际恢复一次。只生成备份文件但从未恢复，不算完成备份。

01

备份 PostgreSQL

mkdir -p backups docker compose exec -T db sh -c \ 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \ > backups/dikong-$(date +%F-%H%M).dump
02

恢复 PostgreSQL

仅恢复到空库或经过确认的目标库，执行前停止写入并再次备份当前数据。

docker compose exec -T db sh -c \ 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' \ < backups/<backup-file>.dump
03

备份与恢复对象存储

使用 Compose 中已有的 MinIO Client 镜像，凭据只在容器环境中读取。

mkdir -p backups/minio docker compose run --rm --entrypoint /bin/sh \ -v "$PWD/backups/minio:/backup" minio-init -c \ 'mc alias set source http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" && mc mirror --overwrite "source/$OBJECT_STORAGE_BUCKET_NAME" /backup' # 恢复时确认目标 bucket 后执行 docker compose run --rm --entrypoint /bin/sh \ -v "$PWD/backups/minio:/backup" minio-init -c \ 'mc alias set target http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" && mc mirror --overwrite /backup "target/$OBJECT_STORAGE_BUCKET_NAME"'
备份文件必须复制到部署主机之外，并设置加密、访问权限、保留周期和定时任务。不要把备份提交进 Git。

更新与回滚

更新前记录当前 commit 并完成备份；先查看迁移，再重建应用容器。

01

更新版本

git rev-parse HEAD git fetch --all --tags git checkout <new-release-tag-or-commit> docker compose build web v2-dji-worker docker compose run --rm web python manage.py migrate --plan docker compose up -d web v2-dji-worker
02

回滚应用版本

数据库迁移是否可逆必须按发布内容单独确认；不可逆时从升级前备份恢复。

git checkout <previous-commit> docker compose up -d --build web v2-dji-worker docker compose ps
