选择场景

本地调试给出可直接启动的默认写法；正式部署保留生产安全默认值。

常用默认写法：本地

DB_ENGINE=postgres DJANGO_DEBUG=true DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1 OBJECT_STORAGE_ENDPOINT_URL=http://127.0.0.1:9000

常用默认写法：正式

DB_ENGINE=postgres DJANGO_DEBUG=false DJANGO_ALLOWED_HOSTS=api.example.com OBJECT_STORAGE_ENDPOINT_URL=https://files.example.com
先启动向导，不要先启动正式应用容器：docker compose up -d --build onboarding

DJI 连接

DJI 上云地址、账号和密码由平台用户配置，保存在 PostgreSQL 的 DjiConnection 记录里，不写入部署环境变量。

不是 DJI 上游账号。只有上云侧要主动推送媒体上传结果时才填；不需要可留空。{{ config_errors.DJI_INTERNAL_API_TOKEN }}
系统启动后，由平台管理员在资源中心创建 DJI 连接： baseUrl=https://dji-upstream.example.com username=<upstream-user> password=<upstream-password> loginFlag=1

启动系统

保存配置后停止向导，再按顺序启动基础设施和应用。

1. db

PostgreSQL 16，保存业务数据、账号、权限和任务状态。

2. redis

Channels、WebSocket 广播和 DJI worker 协作。

3. minio + minio-init

对象存储常驻，初始化任务负责创建 bucket。

4. web + v2-dji-worker

ASGI API 和 DJI MQTT 后台处理同时启动。

docker compose stop onboarding docker compose up -d db redis minio minio-init docker compose up -d --build web v2-dji-worker docker compose ps
