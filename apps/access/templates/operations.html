日志与排障

先定位服务，再看最近 200 行。

01

查看服务状态

docker compose ps
02

查看日志

docker compose logs -f --tail=200 web docker compose logs -f --tail=200 v2-dji-worker docker compose logs -f --tail=200 db docker compose logs -f --tail=200 redis docker compose logs -f --tail=200 minio

备份与恢复

备份完成后必须在测试库恢复一次，确认文件真的可用。

01

备份 PostgreSQL

mkdir -p backups docker compose exec -T db sh -c \ 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \ > backups/dikong-$(date +%F-%H%M).dump
02

恢复 PostgreSQL

只恢复到空库或经过确认的目标库，执行前停止写入并再次备份当前数据。

docker compose exec -T db sh -c \ 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' \ < backups/<backup-file>.dump
03

备份与恢复对象存储

mkdir -p backups/minio docker compose run --rm --entrypoint /bin/sh \ -v "$PWD/backups/minio:/backup" minio-init -c \ 'mc alias set source http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" && mc mirror --overwrite "source/$OBJECT_STORAGE_BUCKET_NAME" /backup' docker compose run --rm --entrypoint /bin/sh \ -v "$PWD/backups/minio:/backup" minio-init -c \ 'mc alias set target http://minio:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" && mc mirror --overwrite /backup "target/$OBJECT_STORAGE_BUCKET_NAME"'

更新与回滚

更新前记录当前 commit 并完成备份；先查看迁移计划，再重建应用容器。

01

更新版本

git rev-parse HEAD git fetch --all --tags git checkout <new-release-tag-or-commit> docker compose build web v2-dji-worker docker compose run --rm web python manage.py migrate --plan docker compose up -d web v2-dji-worker
02

回滚应用版本

数据库迁移是否可逆必须按发布内容单独确认；不可逆时从升级前备份恢复。

git checkout <previous-commit> docker compose up -d --build web v2-dji-worker docker compose ps

重启与停服

保留数据时只停止容器，不删除卷。

01

重启应用

docker compose restart web v2-dji-worker
02

停服并保留数据

docker compose down
正式环境禁止执行 docker compose down -v。它会删除 PostgreSQL 和 MinIO 数据卷。
