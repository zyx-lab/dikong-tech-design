# 角色权限矩阵设计（V4 / 当前实现）

本文件描述当前代码中已落地的角色权限矩阵，覆盖：
1. Formal IAM Plane（`/api/v1/iam/*`）
2. Business Plane（`/api/v1/*`）

统一规则：
- 权限来源：`permissions`
- 角色来源：`roles`
- 授权链：`TenantMemberRole -> RolePermissionGrant -> Permission`
- scope 优先级：`ALL > ASSIGNED > OWN`
- 默认拒绝：有权限但无合法 scope 配置时拒绝
- 禁用 `user_permissions` 直配
- 禁用用户直绑 `Group`
- `platform_admin` 只允许平台工作态使用，不允许分配给租户成员

## 4. 关键行为说明

1. `pilot_operator` 在无人机、任务、飞行记录、媒体文件上统一走 `ASSIGNED`。
2. `ASSIGNED` 的主体统一按当前租户内的 `TenantMember.id` 判定。
3. `tenant_admin` 是租户侧最高权限，额外拥有成员目录、角色分配与租户审计能力。
4. `business_admin` 拥有全量业务权限，但不管理成员与角色分配。
5. `platform_admin` 只做平台治理，不直接进入租户成员治理。
6. waypoint 已降级为 route 聚合内部结构，不再存在 `waypoint.*` 独立权限；航点编辑能力并入 `route.manage_route`。
7. `/api/v1/__internal__/dji/*` 不走租户 RBAC；它们通过 `X-DJI-Internal-Token` 做系统内部鉴权。

## 5. 初始化命令

```bash
python manage.py migrate
python manage.py seed_role_permissions --mode replace
```

补充：

```bash
python manage.py create_business_admin_account --username biz_root --password 'YourStrongPassword'
```

说明：
1. 该命令只创建正式业务账号与 `StaffProfile`。
2. 该命令不会直接授予租户角色。
